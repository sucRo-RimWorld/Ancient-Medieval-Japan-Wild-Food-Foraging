# Tree-nut collection mechanism — source comparison (2026-10-14)

**Status:** research only; implementation entry **HOLD**. This is a scoped evidence note, not a validated Project `status=ready` decision, implementation design approval or runtime PASS.

## Concrete requirement

An already spawned Environment-owned Japanese tree must allow pawns to collect **edible tree products independently from chopping timber**. Collecting must not remove or reset the tree's wood pool, and cutting must retain its existing Vanilla/MO timber output without granting an unintended duplicate edible harvest. The mechanism should work on an old AMJE map and be reusable by future individually accepted trees. No new species, quantity, season, recipe or packageId is approved.

### Native-path limitation

The prior 2026-10-10 source review in [ExistingModAudit.md](ExistingModAudit.md) mapped `JobDriver_PlantWork`, `JobDriver_PlantCut` and `PlantCollected`: the existing jobs share primary harvest item selection; cutting subsequently destroys the tree. The pinned decompiled snapshot became unavailable through GitHub on 2026-10-14 (HTTP 451, repository access blocked). This review **reuses the previously retained observation**; it does not claim fresh inspection, a local 1.6 assembly decompilation or a native engine pass.

## Alternatives and bounded result

1. **Data-only fruit primary with `harvestAfterGrowth`: reject for existing Shii/Beech.** That rewrites the Environment wood path; retrofitting `butcherProducts` on cut is insufficiently tested, especially for MO and unmarked vegetation clearance.
2. **VEF secondary-output extension: reject for independent action.** It fires at the shared collection callback, not only at nut picking; VEF must remain optional.
3. **Separate native harvest designation routed to a different, tree-preserving fruit job: candidate, not yet approved.** Check whether existing job/comp/WorkGiver hooks can separate the output without new bespoke work types or new designators; introduce narrowly scoped C# only after proving no simpler viable source alternative. Must not touch Environment timber Defs or substitute an inexhaustible collection building.

**Gate:** no `status=ready` record yet. Continue with direct non-VE successor implementation/source inspection, Engine/MO loaded native harvest-vs-cut and save compatibility, then record the smallest admissible mechanism in Design before production code. Mushrooms and famine foods remain separate candidate decisions. This scope does not authorize delaying unrelated Environment/Grains work.

### Decision-relevant mechanism separation

- **Vanilla 1.6 crop harvesting / Ratkin additional yield / VEF DualCrop:** primary tree wood harvest callback is shared with cutting. If simply patched onto Shii, harvesting risks dropping wood alongside nuts and/or nuts on cutting.
- **MO/VPE/VV/VGP orchard pattern:** fruit/nut is the tree's primary yield and native regrowth retains the tree; switching Shii to fruit would replace its original timber-primary contract and enter untested MO wood conversion/old-save behavior.
- **More Tree Products / Bunny Framework:** drops nuts or similar secondary products on **destroy**, not on a standing tree harvest.
- **Vivi:** **proves a technically distinct, stateful, target-plant gathering path is implementable** at source level without altering the target tree's primary yield. Direct code reuse/mandatory dependency is inappropriate: Biotech + Harmony + race, gathering table/recipe/biome/arcane systems and absent explicit reuse license.
- **EBSG:** separate job exists but tied to an abstract gather site, the wrong environmental resource model.

**Narrow implementation *proposal*, still subject to formal Project entry decision and balance/UI approvals:** build an AMJ-owned, **original-code** tree-preserving gather Job on eligible **Environment-owned** `AMJ_Tree_Shii` instances, with separately saved finite eligibility/cooldown; never call `PlantCollected` or `Destroy` when gathering; leave original cut and MO WoodChain unchanged, and reject the action if tree disappears, becomes forbidden, is unreachable, burning, or no longer eligible. Prefer an individual tree designation over Vivi's **mandatory gathering bench**, and evaluate native right-click/WorkGiver support against the existing design. No exact JobDef, thing product, cooldown duration, season, food quantity or UI is hereby approved.

**Preservation and test obligations remain:** `ThingComp` added to an *already saved* `Plant` requires real old-save load/re-save and remove/re-add testing; Gizmo/designation races and multiple pawns need authoritative F06; cooldown save under F05; MO/CCTO profiles remain F03/F12. Zero RimWorld native tests were run for this finding.

**Bounded source exclusion:** VV Trees exact `ThingDef` and EW2 live cut/wood code remain unacquired, but their currently advertised *fruit-primary orchard* and *woodworking* functionality is not direct evidence of a separate living-tree product collector. Other wild edible fungi/famine-food Mods matter to **later mushroom/food slices**; this source comparison applies only to **initial Shii gathering mechanics**. No source or art has been copied from upstream.
