## Implications for AMJ

1. The earlier notion that only MO and VPE were compared is **superseded for discovery**: VV's dedicated tree/nut module and VGP are now explicit material non-VE alternatives. VV contains an already implemented **chestnut** candidate, so the planned new Environment Kuri tree requires a genuine nonduplicate-gameplay justification; prior AMJE author approval remains *candidate only*.
2. **Existing wood-primary Shii/Beech is a different requirement from adding a new fruit-primary orchard tree.** Current directly inspected VPE/MorePlants XML does not solve it. Non-VE content descriptions are not proof either.
3. Do **not** add mandatory VV/VPE/VGP dependencies, new species, product definitions, recipes, invented weights or custom C# solely because alternatives exist. Keep Environment → Foraging ownership; use optional interoperability when direct functional equivalence is proven and the user wants it.
4. Next evidence work: obtain actual current VV Trees `ThingDef` and native cut/gather behavior (especially chestnut), plus VGP fruit-source XML; compare with MO/Environment timber and investigate `butcherProducts` on **real** 1.6 jobs. Bound fungal/famine audit separately; avoid representing the entire VV catalog as a prerequisite.
5. **Status stays HOLD** for new production implementation: no verified Project-format `status=ready` decision; runtime F01–F14 remain NOT RUN. These are stronger candidate inventories, not false compatibility PASS.

**Evidence levels:** VE and VV companion = actual GitHub 1.6 source; VV base and VGP = Workshop/dated catalog descriptions; Expanded Woodworking successor = changelog assertion, no source/native proof.

## 2026-10-14 — primary-source/loaded-log follow-up for VV and VGP

**VV Trees author confirmation (not source XML):** [standalone Trees Workshop page](https://steamcommunity.com/sharedfiles/filedetails/?id=3552455805), directly opened on 2026-10-14, identifies Trees **5.0**, listing **RimWorld 1.6 and 1.7** and an **2026-10-13** update (page's timestamp), **20 fruit/nut tree species**, no external required Mods, and optional compatibility patches for natural wild spawning. In the 2026-08-12 comments VVenchov answers the question about trees being fully cut at harvest: trees remain alive and smaller, then bear fruit again after waiting; their lifecycle allows multiple harvests. The same page explicitly states the implementation uses **only basic XML definitions** and does not overwrite Vanilla files. This establishes the author's *claimed user-visible* renewable-fruit behavior and implementation category, but it is **not the current actual 1.6 PlantDef XML, code inspection or a loaded-game test**. It gives no source-grounded proof of a separate timber-cut yield, a distinct gather Job, an attachable extension for `AMJ_Tree_Shii`, or how old-save trees react to added comps. The publicly declared **CC BY-NC-ND 4.0** license further rules out casually reusing/adapting its shipped art/Defs as AMJ source; *comparison* and *ordinary optional coexistence* are different from copying.

**VV source accessibility:** ordinary GitHub repository searches for `VV New Harvest`, `NewHarvest`, `VVenchov`, `vvenchov.vvnewharvesttrees`, plus web source search did not locate the **author's main Trees XML repository**. The author's public [version archives](https://drive.google.com/drive/folders/1BHOytICOP9YFrVlc4-QDBgx2PeKZD-_k?usp=sharing) are linked from the standalone Trees Workshop item, but the available text browser did not expose actual XML; in the current isolated environment public Drive access could not be materialized as bytes. **This is a precise missing-artifact limitation, not evidence of nonexistent source or a request for the user to relay it.** A third-party [VV compatibility companion source](https://github.com/octodecoy/VV---New-Harvest-Compatibility-Patches---Release) is *not* the original VV tree source.

**VGP evidence upgraded from catalog-only to a particular real 1.6 log excerpt (not source checkout):** [HugsLib published RimWorld log](https://gist.github.com/HugsLibRecordKeeper/ffce6c0b499b77f760c6c41388d1da80#L3231-L3346) reproduces `[Rimworld_dir]/Mods/2007061826_VGP Vegetable Garden/1.6/Defs/ThingDefs_Plants/Cultivated_Plants_Fruit.xml` context. Its apple (`Rawapple`), peach (`Rawpeach`) and cherry (`RawCherry`) tree snippets set `harvestTag=Standard`, `harvestAfterGrowth=0.30`, and their named **fruit** as primary `harvestedThingDef`; the log shows yields **50** in cultivated examples and **20** in other specimens. Other cited 1.6 XML contexts include orange and fig, likewise fruit-primary. That is genuine *copied loaded-file context in a third-party error report*, **not** our independently inspected full VGP XML or a successful runtime PASS; the displayed `leaflessSnowOverlayGraphicPath`/`snowOverlayGraphicPath` errors mean one reporter had unsupported XML fields, not that all VGP installations fail or the same version is current. It demonstrates **VGP uses the same fruit-primary / regrow pattern as MO and VE**, not a separate side harvest on timber-primary Shii.
